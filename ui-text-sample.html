UI Text & Content Design

Before/after interface copy for GradePath, a fictional grading and assessment platform — error messages, empty states, onboarding, and confirmation dialogs.

GradePath is a fictional product, built so I can show UI text decisions without exposing proprietary interface copy from past employers. The scenarios below — file upload errors, empty gradebooks, first-time setup, grade submission — reflect the kind of content design work I've done in production for real SaaS platforms and industrial software, reframed here around an education tool.

Content principles

  • Lead with the fix, not the failure. Tell people what to do next, not just what went wrong.
  • Match the stakes. A typo warning and a "submit final grades" warning shouldn't sound the same.
  • Name specifics. Course names, file types, character counts — vague copy creates support tickets, not fewer.
  • Assume good faith. Never word copy as if the user did something wrong on purpose.

Examples

Error message — failed file upload
Before Error: Upload failed. File type not supported.
After That file didn't upload — GradePath accepts PDF, DOCX, and JPG rubrics. Try converting the file, or upload a different one.

Why: The original blames the action without offering a path forward. The rewrite names the fix immediately and lists accepted formats, so the instructor doesn't have to guess or open a support ticket.

Empty state — no submissions yet
Before No data available.
After No submissions yet. Once students turn in their work, you'll see it listed here — sorted by due date.

Why: "No data available" reads like a system error, not a normal state. An empty state should reassure the user that nothing is broken and tell them what to expect next.

Onboarding — first-time course setup
Before Please configure your grading scale before continuing.
After Set up your grading scale — you can always change it later. Most instructors start with a standard A–F scale.

Why: "Please configure" is a command with no context. The rewrite lowers first-time friction by normalizing the decision and offering a default, which matters most during onboarding, when users are still deciding whether to trust the product.

Confirmation dialog — submitting final grades
Before Are you sure? This action cannot be undone.
After Submit final grades for Fall 2026 – Biology 101? Grades will be visible to students immediately and can't be edited after submission.

Why: Generic confirmation dialogs create anxiety without giving enough information to decide. Naming the specific course and the specific consequence lets the instructor confirm with full information instead of just trusting a warning.

Inline validation — form field
Before Invalid input.
After Assignment names need to be 60 characters or fewer — try shortening it by 12 characters.

Why: Telling someone their input is "invalid" without saying why turns the form into a guessing game. Naming the constraint and the exact gap turns a dead end into a next step.
